Wednesday · Trusted Advisor (Interactions API、Tool Retrieval 与 Computer Use 安全治理)

Stateful Agent Execution, Schema Retrieval, and HITL Guardrails

Walking an enterprise architect through native Interactions API sessions, server-side Tool Retrieval, and Org Policy constraints on Computer Use.

Pace
Voice
I. Stateful Interactions API: Eliminating Context Bloat and Client Shuffling

When your development teams transition from prototype scripts to enterprise agentic workflows, David, / the standard `GenerateContent` REST loop becomes an architectural bottleneck. / Historically, client apps had to persist the entire conversation history, serialize tool outputs, and re-transmit hundreds of thousands of tokens on every single turn. / The newly GA Interactions API models stateful sessions natively on Google Cloud—mirroring OpenAI's Responses API spec. / The server automatically manages conversation turns, tracks asynchronous tool executions, and provides unified streaming, / removing massive network payloads and client-side state plumbing.

David，当你们研发团队从原型脚本迈向企业级 Agent 工作流时，传统的 GenerateContent REST 循环就变成了架构瓶颈。以往客户端必须在本地持久化全量对话历史、序列化工具返回结果，并在每一轮请求中重复上传数十万 token。本周正式 GA 的 Interactions API 在 Google Cloud 服务端原生支持有状态会话（Stateful Sessions），接口规范对标 OpenAI Responses API。服务端自动管理对话轮次、跟踪异步工具执行并提供统一流式响应，彻底消除了庞大的网络载荷与客户端会话管理负担。

II. Server-Side Tool Retrieval: Cutting Cost for Massive MCP Catalogs

The second breakthrough in the Interactions API is Tool Retrieval, currently rolling out in EAP ahead of Public Preview. / In production, sophisticated enterprise agents often require access to fifty, eighty, or more Model Context Protocol (MCP) servers— / spanning Salesforce, Jira, SAP, and custom database endpoints. / Forcing every tool schema into the initial system prompt instantly consumes twenty to thirty thousand input tokens per invocation. / By configuring `defer_loading=true`, the model dynamically evaluates user intent server-side and retrieves only the specific tool schemas required for that turn, / slashing first-token latency, input token spend, and rate-limit friction.

Interactions API 的第二项突破是工具检索（Tool Retrieval），目前处于 EAP 阶段并即将转入 Public Preview。在生产环境中，复杂的企业级 Agent 通常需要挂载 50 到 80 个甚至更多的 MCP 工具——涵盖 Salesforce、Jira、SAP 及自建数据库接口。如果把所有工具 schema 硬塞进初始 system prompt，单次调用就会瞬间吃掉两三万 input tokens。通过配置 `defer_loading=true`，模型会在服务端按需动态评估用户意图，只检索当前轮次所需的工具定义，大幅削减首字延迟、input token 成本与并发限流压力。

III. Computer Use Tool GA: Enterprise HITL Governance & Org Policy Guardrails

Finally, on November sixth we brought our Computer use tool into General Availability. / The central friction point for IT security officers evaluating agentic desktop control has always been the fear of autonomous hallucination. / Our GA release addresses this directly through comprehensive Human-in-the-Loop (HITL) policy controls. / Developers can configure granular confirmation gates for high-risk operations—such as bank wire transfers or production database updates. / Crucially, central IT administrators can enforce organization-wide safety boundaries using the `configurableComputerUseToolSafetyPolicies` Org Policy constraint, / guaranteeing that unverified actions are intercepted before execution.

最后，我们在 11 月 6 日正式将 Computer use tool 推向 GA。企业安全高管评估 Agent 桌面操控能力时，最大的痛点始终是对自主失控与幻觉的担忧。我们的 GA 版本通过完备的 Human-in-the-Loop（HITL）策略控制直接化解了这一顾虑。开发者可以为高风险操作（如资金转账或生产数据库修改）配置细粒度的人工二次确认门禁。更关键的是，中央 IT 管理员可以通过 `configurableComputerUseToolSafetyPolicies` 组织级约束策略强制实施全局安全边界，确保未经验证的高危操作在执行前被彻底拦截。

90-Sec Executive Pitch · Interactions API & Computer Use Safety

The newly GA Interactions API eliminates client-side context shuffling by managing stateful sessions natively on Google Cloud. / With Tool Retrieval in EAP (`defer_loading=true`), agents dynamically load only the MCP schemas required for that turn, slashing token bloat across large catalogs. / Meanwhile, the GA of Computer use tool introduces enterprise-grade Human-in-the-Loop governance and the `configurableComputerUseToolSafetyPolicies` Org Policy constraint, / ensuring sensitive actions require explicit confirmation.

新 GA 的 Interactions API 通过在 Google Cloud 服务端原生托管有状态会话，免去了客户端反复拼接上下文的麻烦。配合处于 EAP 的 Tool Retrieval（`defer_loading=true`），Agent 可以在服务端按需加载 MCP 工具定义，大幅压缩大型工具集的 token 消耗。同时，Computer use tool 正式 GA，引入了企业级 HITL 安全治理机制与 `configurableComputerUseToolSafetyPolicies` 组织级约束，确保敏感操作必须经过显式确认。
